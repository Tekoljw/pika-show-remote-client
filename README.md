# PIKA-Show 远程客户端

装在直播间那台 **Windows** 电脑上跑的程序。只支持 Windows，不做跨平台——现场那台灯控电脑就是 Windows，没必要为了理论上的跨平台能力多花工夫。

2026-09 起带一个简单图形界面(`@webviewjs/webview`，Windows 下走系统自带的 WebView2，不是 Electron)：连接开关、填连接密钥、改设备名字、检查更新。

## ⚠️ 这个仓库没有源码

**这个仓库只放 [`.github/workflows/build.yml`](.github/workflows/build.yml) 这一份构建脚本，不存放任何产品源码。** 源码在 [`PIKA-Show`](https://github.com/Tekoljw/PIKA-Show) 私有主仓库的 `remote-client/` 目录——这个公开仓库存在的唯一目的是借用 GitHub 公开仓库的免费无限 Actions 分钟数、用真实 Windows Runner 编译 + 冒烟测试，构建时用一把只读部署密钥现场检出私有仓库的代码来编译，构建完直接发布 Release，公开侧不会留下、也从来没有留下过完整的产品代码。

如果你在找源码：这里没有，是私有的。如果你在找**下载**：看下面。

## 下载

去 [Releases](https://github.com/Tekoljw/pika-show-remote-client/releases) 页面下载 `PIKA-Show-Setup-v<版本>.exe`——双击、下一步、完成，自动装好捆绑的 QLC+、自动配开机自启动。**这是唯一需要人工下载的文件**（Release 页面上还会看到一个 `pika-show-remote.exe`，那个只给客户端自己热更新用，不需要手动管）。

## 依赖

- [QLC+](https://www.qlcplus.org/)——2026-09-14 起**打包进了分发产物里，不用用户自己单独装**（Apache 2.0 协议允许这样重新分发）。如果这台电脑本来就单独装过 QLC+、又没有这个捆绑目录，会退回系统 PATH 里找，也可以用 `QLCPLUS_BIN` 环境变量显式指定
- Windows 10 1809 及以上 / Windows 11 通常已经自带 WebView2 运行时；老系统缺失时 Microsoft Edge 会自动补装，一般不用额外操心

## 界面说明

打开后一个窗口，几个卡片：

- **连接状态**：显示有没有连上 PIKA-Show 服务端，旁边一个"连接/断开"按钮——断开只是停掉这条远程连接，本地 QLC+ 不受影响
- **连接密钥**：第一次跑、本地还没存密钥时才会出现这张卡片，把 Telegram 里"🔑 远程Key"发来的密钥粘贴进去提交，粘一次以后自动记住(DPAPI 加密存本地)，断线自动重连不用再填
- **管理员 TG ID**：认证成功后自动显示——是密钥归属的那个 Telegram 用户，不是手填的
- **设备名字**：改了点保存，直接同步到云端，PIKA-Show 的 miniapp/管理后台里看到的就是这个名字
- **检查更新**：程序一打开就会自己悄悄查一次，有新版会自动下载替换、自动重启，不用手动点。这两个按钮是手动备用入口，不想等启动查、现在就想手动查一下也可以点

## 配对

密钥直连——**本地会存一份密钥**（DPAPI 加密，只有这台机器 + 这个 Windows 账号能解开），第一次跑或者本地没有密钥时才弹密钥输入卡片。在 Telegram 里点底部键盘"🔑 远程Key"，bot 会私聊发一条密钥消息（5 分钟后自动撤回），粘贴进客户端提交即可——只有一次性操作，以后每次启动或断线都会自动用这把密钥重连，不需要再人工干预。密钥被管理后台吊销后，本地这份会被清掉，重新弹出输入卡片，需要回 Telegram 重新申请一把。

## 检查更新 / 热更新

**程序启动那一刻会自动查一次**这个仓库的最新 Release，跟当前版本号比对，有新版就自动下载、替换、重启，不需要点任何按钮。只在启动那一刻查——运行起来之后不会再反复检测、不会在直播过程中忽然自动重启。界面上的"检查更新"/"立即更新"两个按钮是手动备用入口，逻辑跟启动时的自动检查完全一样：下载 `pika-show-remote.exe`（**不是**安装向导那个文件）→ 等当前进程退出 → 直接覆盖当前这个程序文件 → 重新拉起，不弹任何安装界面。

⚠️ **这条热更新只替换程序本体，不会动 `qlcplus/` 这个捆绑目录**——QLC+ 版本升级现在又需要整个重新下载 `PIKA-Show-Setup-v<版本>.exe` 装一遍了（跟直接覆盖文件这个更新方式互斥，这是明确接受的取舍）。

新版本的发布是 CI 自动做的：私有主仓库改代码、提版本号、push 之后，手动触发一次这个仓库的 `build.yml`（`workflow_dispatch`），构建通过后按版本号自动建一个新 Release，挂两份资产（人类下载装的安装向导 + 热更新用的裸 exe，见上面"下载"一节）。

## 环境变量（都是可选的，不设就用默认值）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PIKA_SHOW_HOST` | `show.pika.club` | 服务端域名 |
| `QLCPLUS_BIN` | 优先用打包时捆绑的那份，没有才退回 PATH | QLC+ 可执行文件完整路径，显式指定的优先级最高 |
| `QLCPLUS_PORT` | `9999` | QLC+ 内建 Web API 端口 |
| `QLCPLUS_WORKSPACE` | 无 | 启动时自动加载的配接方案(`.qxw`)文件路径 |
